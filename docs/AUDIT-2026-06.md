# Kuza ERP — Production-Readiness Audit

**Date:** 2026-06-12
**Auditors:** Inventory SME · Accounting SME/CFO · Solution Architect · Product/Frontend Lead
**Method:** Direct code review of `backend/src` and `frontend`. Findings carry `file:line` evidence.

> Verdict in one line: **A well-architected multi-tenant operational system (IMS/HRMS/RMS) sitting on top of a non-existent accounting backbone and an unsafe stock model. Operationally usable, not yet financially trustworthy or enterprise-sellable.**

## 2. Critical findings (block production)

### Inventory
- **C-INV-1 — Stock is a mutable column, not a ledger.** `InventoryItem.currentStock` and `BranchInventoryItem.currentStock` are mutated in place (`inflows.service.ts:205`, `orders.service.ts:448`). No immutable `stock_movements` table. Balances can drift and cannot be recomputed. **This violates the directive's "movements must be the single source of truth."**
- **C-INV-2 — Inflows are not transactional.** `inflows.service.ts:83-341` creates inflow + items + batches + stock updates with `Promise.all` and **no QueryRunner/transaction**. Partial failure → orphaned stock increases.
- **C-INV-3 — Order stock deduction not transactional.** `orders.service.ts:401-472`. Order can persist with stock never deducted → overselling.
- **C-INV-4 — Allocation race condition.** FIFO allocation reads "quantity sold" then writes, with no `SELECT … FOR UPDATE` (`orders.service.ts:161-175`). Concurrent orders oversell the same batch.

### Accounting
- **C-ACC-1 — No double-entry accounting exists at all.** No Chart of Accounts, Journal, GL, Trial Balance, AR/AP. Confirmed by exhaustive grep. Sales, purchases, payroll, transfers create **zero** financial records. A business cannot close its books.

### Security / Tenancy
- **C-SEC-1 — Empty migration staged.** `1706976000000-RemoveBusinessIdFromMultiTenant.ts` and its `.sql` are **0 bytes**. Do not run as-is.
- **C-SEC-2 — Hard-coded/default JWT secret** (`auth.module.ts:34`, `jwt.strategy.ts:16`, docker-compose default). Forge any tenant's token.
- **C-SEC-3 — `DB_SYNCHRONIZE=true` default + hardcoded in landlord config** (`landlord-database.config.ts:22`). Schema auto-mutation in prod = data-loss risk.
- **C-SEC-4 — Permission bypass:** users with no roles are granted full access (`permissions.guard.ts:31-36`, `return true`).
- **C-SEC-5 — Google OAuth has no tenant context** (`auth.service.ts:378-411`); JWT gets `tenantId: undefined`, breaking isolation.
- **C-SEC-6 — Schema switch via shared pooled connection** (`tenant-connection.service.ts:26-29`). Concurrent requests can execute against the wrong tenant's schema (`SET search_path` is connection-scoped, pool is shared). **Cross-tenant data leak.**

## 3. High findings
- No stock ledger / audit trail (recompute & compliance impossible).
- No Purchase Order → GRN → 3-way match.
- No inventory adjustments / write-offs with reason codes & approval.
- UOM conversion has no graph traversal (`uom-conversions.service.ts:144`) — multi-hop units fail.
- FEFO is hard-coded to FIFO (`orders.service.ts:278` TODO); expired stock can be sold.
- No weighted-average cost stored; valuation recomputed on the fly.
- Payroll posts no GL entries (`payroll/payroll.service.ts:173`).
- No audit-log entity anywhere; no rate limiting on auth; password hashed value returned in user API responses.
- No connection pool sizing; query-level tenant filtering inconsistent.

## 4. Medium / commercial gaps
- No customer master / AR aging; no invoicing, receipts, discounts, refunds in RMS.
- No fixed-asset module or depreciation.
- Multi-currency stored but no FX rates or gain/loss.
- Tax is payroll-only & US-centric; no sales/purchase tax GL.
- No data export (Excel/PDF); no report builder.
- Performance/Recruitment/Learning HRMS submodules are stubs.
- Mobile (Flutter) is scaffolding only.

## 5. Target double-entry postings (Accounting SME reference)
| Business event | Debit | Credit |
|---|---|---|
| Goods receipt (inflow) | Inventory | Accounts Payable (or Cash) |
| Sale | COGS / Accounts Receivable | Inventory / Sales Revenue |
| Sales tax on sale | — | Tax Payable |
| Customer payment | Cash/Bank | Accounts Receivable |
| Supplier payment | Accounts Payable | Cash/Bank |
| Inventory write-off/adjust | Inventory Adjustment Expense | Inventory |
| Inter-branch transfer | Branch B Inventory | Branch A Inventory |
| Payroll | Wage Expense | Wages Payable / Tax Payable |
| Payroll payout | Wages Payable | Cash/Bank |
| Asset purchase | Fixed Asset | Cash/AP |
| Depreciation | Depreciation Expense | Accumulated Depreciation |

**Invariant:** no transaction may affect the business financially without a balanced (Σ debits = Σ credits) journal entry.
